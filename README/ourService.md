Services page around 8 families

Your current seven are already strong. I'd add one important family: Assess.

That gives you:

01 — Build

Create something new.

02 — Improve

Make existing technology better.

03 — Move

Migrate technology and data.

04 — Connect

Integrate systems and services.

05 — Protect

Improve security, resilience and recovery.

06 — Operate

Maintain, monitor and support.

07 — Deploy

Put technology into production.

08 — Assess

Understand what is wrong and what should change.

That last category is important because not every client knows what service they need.

01 — BUILD
Create technology built around your business.

This is where River develops something specifically for a client.

Services:

Custom Software Development
Web Application Development
Mobile Application Development
Custom Business Systems
Internal Tools & Platforms
API Development
Custom Portals
Workflow Automation

The distinction from Products should be very explicit:

Products: Start with an existing River solution.
Build services: Start with your requirements.

This means a company doesn't have to decide whether what they need is a "product" or "custom software."

River can guide them.

02 — IMPROVE
Make existing technology faster, better and more effective.

This could actually become one of River's strongest commercial categories because many businesses don't need a replacement.

They need someone to fix what they already have.

Services:

Website Speed Optimization
Application Performance Optimization
Database Optimization
Frontend Optimization
Backend Optimization
UX/UI Improvement
Technical SEO
Legacy System Modernization
Codebase Refactoring
Accessibility Improvements

Your core message could be:

Your system doesn't always need to be replaced. Sometimes it needs to be improved.

That's a very good positioning statement for River.

03 — MOVE
Move your technology without losing what matters.

Services:

Cloud Migration
Server Migration
Website Migration
Database Migration
Platform Migration
Hosting Migration
Application Migration
Data Migration

And importantly, don't make this sound like:

"We move your files."

Make it sound like engineering.

Assess → Plan → Migrate → Validate → Switch → Monitor

That communicates that River understands migration risk.

04 — CONNECT
Make your systems talk to each other.

Services:

API Integration
Payment Integration
Third-Party Integrations
System Integration
ERP/CRM Integration
Data Synchronization
Webhooks & Event Integration
Authentication Integration
API Development

This category has an incredibly simple customer proposition:

Your systems shouldn't work in isolation.

And you can visually demonstrate:

CRM
  ↕
Business System
  ↕
Payments
  ↕
Website
  ↕
Mobile App
  ↕
External APIs

This also makes River look like a systems engineering company, rather than simply a web developer.

05 — PROTECT
Keep your technology secure, recoverable and resilient.

Services:

Security Hardening
Application Security
Infrastructure Security
Authentication & Access Control
Security Audits
Backup & Recovery
Disaster Recovery

I'd be careful about presenting this as "cybersecurity" unless River is actually offering a comprehensive cybersecurity service.

Instead, position it around technical security and resilience.

06 — OPERATE
Keep your technology running after it goes live.

Services:

Website Maintenance
Application Maintenance
Technical Support
Monitoring
Backup Management
Server Management
Performance Monitoring
Updates & Patching
Incident Troubleshooting
Managed Technical Support

This is where you can introduce a very strong proposition:

Your team shouldn't have to become a software engineering team just to keep your systems running.

River becomes the technical partner behind the scenes.

07 — DEPLOY
Take technology from development to production.

Services:

Cloud Deployment
Server Configuration
Infrastructure Setup
CI/CD
Production Deployment
Environment Configuration
Domain & Hosting Configuration

Deployment Automation

This category can also connect naturally to your technical credibility section.

For example:

Development → Staging → Testing → Production → Monitoring

08 — ASSESS

This is the one I'd add.

Understand the problem before deciding what to build.

Services:

Website Audits
Application Audits
Technical Assessments
Performance Audits
Security Assessments
Infrastructure Assessments
Architecture Reviews
Database Assessments
Migration Assessments
Technical Discovery

This gives River an entry point for clients who say:

"Something is wrong with our system, but we don't know what."

Instead of forcing them to choose:

Speed Optimization

or

Cloud Migration

or

Security Hardening

they can simply say:

Assess Our Technology

River investigates and recommends the appropriate intervention.

That is much more sophisticated.

The Services hero should therefore be different from Products

I wouldn't use something like:

Our Services

Instead:

Technical Work for the Technology You Already Have

Something along the lines of:

Build it. Improve it. Move it. Connect it. Keep it running.

River helps organizations build new technology and improve, migrate, integrate, secure and operate the systems they already depend on.

Then perhaps:

Explore Services
Tell Us What You're Trying to Solve

The second CTA is important.

And I would introduce a “What do you need?” section

This should work almost like the Product Selector you described for Products.

Instead of forcing people to understand River's terminology:

What are you trying to solve?

My website is slow

→ Website Speed Optimization

My system needs to move to the cloud

→ Cloud Migration

Our systems don't communicate

→ System Integration

Our application has bugs

→ Application Maintenance / Bug Fixing

Our old system needs modernization

→ Legacy System Modernization

We need something built

→ Custom Software Development

We're not sure what's wrong

→ Technical Assessment

This is extremely valuable because customers think in problems, not service categories.

Your Services page should also have a “How we work” layer

I'd avoid making the Services page just:

Service → Description → Service → Description → Service → Description

Instead, demonstrate the engagement model.

For example:

From Problem to Working System

01 — Understand

We investigate the current technology, requirements and constraints.

↓

02 — Plan

We determine the appropriate technical approach.

↓

03 — Execute

We perform the work, whether that's building, migrating, integrating or improving.

↓

04 — Validate

We test the result against technical and business requirements.

↓

05 — Handover

We document, deploy and transition the system.

↓

06 — Support

Where required, River continues monitoring, maintenance and improvement.

That ties beautifully into the Product Development Process page you have already built.

I would also add a “We don't always recommend rebuilding” philosophy

This could be a particularly strong River differentiator.

Something like:

The answer isn't always new software.

Sometimes you need a new system.

Sometimes your existing system needs optimization.

Sometimes two systems simply need to communicate.

Sometimes you need to migrate.

Sometimes you need to fix what's already there.

We start with the problem — not the technology.

That sentence fits very well with the River positioning you've been developing.

It reinforces that River isn't simply trying to sell websites or software projects.
